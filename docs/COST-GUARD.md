# ゆっくり解説の原価と黒字の式（COST-GUARD）

> 2026-10-19 作成。正本ポリシー: `ai-generic-rules/docs/policies/COST_SAFETY_POLICY.md`（§A 黒字の式・§3 守りの6層）。
> 対象: `server/src/app/api/yukkuri-explain`（ハンドル解説）と `server/src/app/api/yukkuri-explain-tweet`（ツイート解説）。
> **★表の数字はすべて提案。価格・無料枠の最終決定は本人。** 見積りは公開価格からの概算で、実測で見直す。

## 1. 何が穴だったか（2026-10-19 監査）

- 両ルートとも未ログインで叩ける（`middleware.ts` の `isPublicRoute`）。IP 上限・日次予算なし。
- ハンドル解説は**キャッシュ確認の前に X のプロフィール取得**（有料）を呼んでいた＝キャッシュに当たっても毎回 X に払う。
- 任意・存在しないハンドルでキャッシュを外せた（毎回新しい X＋有料 LLM）。
- ツイート解説はキャッシュが無く、呼ぶたびに X＋有料 LLM。
- OpenRouter の停止スイッチがコードの定数（コミット＋デプロイしないと止まらない）。

## 2. 今の守り（このPRで入れたもの）

| 層 | 中身 | どこ |
|---|---|---|
| L0 物理上限 | OpenRouter の Credit limit（¥10,000 相当・既存）。X は開発者ポータルの支出上限（**要確認・未設定なら設定**） | 提供元のダッシュボード |
| L1 キルスイッチ | `PAID_CALLS_DISABLED=1` で X と有料 LLM を全停止（保存済みの結果は見られる）。`YUKKURI_OPENROUTER_DISABLED=1` で OpenRouter だけ停止 | `server/src/lib/costGuard.ts` |
| L2 日次予算の予約 | X を呼ぶ前・有料モデルを呼ぶ前に `reserveYukkuriBudget` で INCRBY 予約。超えたら戻して呼ばない。Redis 不通・env が読めない → 呼ばない | `server/src/lib/costGuardCore.ts` `reserveMilli` |
| L3 二度払わない | ①メモリ→Upstash→**DB アーカイブ**の順に先に見る（有料呼び出しより前）②存在しないハンドル・取れないツイートは否定キャッシュ（24h）③X のユーザー名として形が正しくない入力は何も呼ばずに 400 ④ツイート解説にも永続キャッシュ（Upstash 30日＋DB） | 各 `route.ts` |
| L4 1人あたりの上限 | キャッシュに当たらなかった呼び出しだけ、IP ごとに 1時間 10回（fail-closed） | `guardPaidEntry` |
| L5 原価の設計 | LLM は無料モデル（`:free`・自前 Ollama）を先に、有料は予算内だけ | `orderModelsFreeFirst` |
| L6 止まったときの見せ方 | 予算切れは 429「本日の無料枠が終了しました」。定型のフォールバック文を「解説」として出さない（キャッシュもしない） | `denialResponse` |

env（すべて任意。★数値として読めない値を入れると「止まる」側に倒れる）:

| env | 既定 | 意味 |
|---|---|---|
| `PAID_CALLS_DISABLED` | 未設定 | `1` で X・有料 LLM を全停止 |
| `YUKKURI_OPENROUTER_DISABLED` | 未設定 | `1` で OpenRouter だけ停止（旧コード定数 `OPENROUTER_DISABLED`） |
| `YUKKURI_DAILY_BUDGET_MILLI` | `3000`（$3/日） | 匿名の日次予算（ミリドル）。`0` で新規解説を全部止める |
| `YUKKURI_IP_LIMIT_PER_HOUR` | `10` | IP ごとの上限（キャッシュ外のみ） |
| `UPSTASH_REDIS_REST_URL` / `_TOKEN` | 既存 | ★未設定だと新規解説は止まる（fail-closed）。保存済みの結果は DB から返る |

## 3. 1回の原価 c（見積り・提案）

| 操作 | 有料呼び出し | 原価 |
|---|---|---|
| ハンドル解説（新規） | X ユーザー1件（≈$0.010）＋ X タイムライン10件（≈$0.050）＋ 有料 LLM 0〜2回（≈$0.003/回。無料モデルが通れば 0） | **≈ $0.060〜0.066 ≈ 9〜10円** |
| ツイート解説（新規） | X ポスト1件＋投稿者（≈$0.015）＋ 有料 LLM 0〜2回 | **≈ $0.015〜0.021 ≈ 2〜3円** |
| 解説済みの表示（キャッシュ・アーカイブ） | なし | **0円** |

★原価の大半は X のタイムライン取得（10件）。`max_results=5` にすれば約半分になる（品質とのトレードオフ・本人判断）。

## 4. 黒字の式（COST_SAFETY_POLICY §A-4）

1ドル = 150円で計算。決済手数料は 3.6% と仮定。

| 項目 | 提案 |
|---|---|
| 原価 c | ハンドル解説 ≈ 10円 / ツイート解説 ≈ 3円（上の表） |
| 無料枠 F | **ログインした人に月 5回**（ハンドル・ツイート合算）。匿名は**保存済みの結果を見るだけ**（新規解説はログイン後） |
| 有料 P/N | **500円 / 30回**（1回 約17円。※300円/30回 だと 300 − 300 − 11 ≈ −11円で赤になるので不可） |
| 有料の粗利 | 500 − 30×10 − 18 ≈ **182円** |
| 無料の原価（1人・月） | F × c = 5 × 10 = **50円** |
| 損益分岐の課金率 r* | 50 ÷ 182 ≈ **27%**（★高すぎる。下の調整案を参照） |
| 匿名の全体予算 | 移行期は `YUKKURI_DAILY_BUDGET_MILLI=3000`（$3/日 ≈ 450円/日）。ログイン導線ができたら匿名は 0 に |
| 最悪の日の損 | 匿名 450円/日（L2 の上限）。月 13,500円。L0（OpenRouter ¥10,000＋X の支出上限）がそれより下で止める |

### r* を現実的（目安 2% 以下）にする調整案（どれか・組み合わせ）

1. **タイムライン取得をやめる／5件にする**: c ≈ 2〜6円 → F×c = 10〜30円。
2. **無料枠を月 1回**にする: F×c = 10円 → r* ≈ 10 ÷ 182 ≈ **5.5%**。
3. **有料パックを 500円/20回**（1回 25円）: 粗利 500 − 200 − 18 ≈ 282円 → 1. と 2. を併用して r* ≈ 2 ÷ 282 ≈ **0.7%**。
4. **ツイート解説を主にする**（c ≈ 3円）: 無料 月5回でも F×c = 15円 → 3. の価格なら r* ≈ 15 ÷ 282 ≈ **5%**。

★推奨（提案）: 「タイムライン 5件 ＋ ログイン無料 月3回 ＋ 500円/20回」→ c ≈ 6円、F×c = 18円、粗利 ≈ 362円、r* ≈ **5%**。
さらに匿名の新規解説を 0 にし、超会議のような大型イベント中だけ `YUKKURI_DAILY_BUDGET_MILLI` を一時的に上げる運用。
